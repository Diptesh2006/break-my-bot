## Opt-in generated scenario execution contract

BreakMyBot now accepts generated individual or cascading fault proposals for execution only when `execute_planned_scenarios` is explicitly enabled together with nRouter planning, an operator-supplied instrumentation configuration, and repeated-call authorization for non-GET targets. The CLI asks separately before planning and before execution; execution is limited to 1–5 scenarios (default 3). The runner inherits the original target URL, endpoint, payload, and instrumentation credential reference. It revalidates each proposal against exact approved fault parameters (`tool`, kind, delay, recurrence, and call number), allows each tool at most once in a generated cascade, checks that every atom is operator-approved, and requires an operator-approved response oracle; invalid proposals are skipped. No proposal can choose a URL, endpoint, payload, or credential. Provider errors do not fall back to execution.

Regression tests use a stubbed nRouter response and an in-process ASGI instrumented target to verify the API/model gate, metadata allowlists, exact fault/oracle matching, one-shot call parameters, execution provenance, and cleanup. The four individual fault recipes used by the comparison are also executed end-to-end against the instrumented fixture, including exception-to-HTTP-500 behavior. The research pilot harness `benchmarks/compare_strategies.py` defines matched fixed, generated-individual, and generated-cascade arms with equal scenario-call budgets, per-call token caps, provider usage/cost accounting, validity, known-recipe discovery, reproducibility, shared controls, and explicit limitations. Harness metrics have unit tests; the live nRouter comparison has not yet been run. On 2026-10-21, the current checks passed: `python -m pytest -q` (54 tests), Ruff, compileall, `git diff --check`, `docker compose config -q`, and `python benchmarks/compare_strategies.py --help`. The Compose command validates configuration only.
